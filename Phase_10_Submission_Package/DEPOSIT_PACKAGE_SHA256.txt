How to reproduce Object 1 - the reason these numbers are recorded here
  git checkout ba0c756c6a14   # the commit the builders were run from
  python3 PAPER_PROJECT/00_Project_Control/make_packages.py final        # standard library only
  sha256sum PAPER_PROJECT/packages/RESEARCH_PROJECT_FINAL.zip             # = the value above

  The builder is deterministic by construction: every entry and MANIFEST.json is written through ZipInfo
  with a fixed timestamp, an explicit compression type and fixed permissions, and nothing inside records a
  build clock or a commit id, so the bytes are a pure function of the working tree: the tracked files plus,
  when present, gitignored DERIVED files (`11_Figures/submission/*.png|tiff` - the 600-dpi PNG and LZW TIFF
  of each of the 8 figures, 16 files, made by
  `python3 Phase_09_Closeout/verification/export_submission_figures.py`). Reproduction never depends on the
  derived set; a deposit copy is only more convenient for a journal. A checkout of the commit above without
  running that exporter yields a 634-file archive whose tracked content hashes identically file-for-file;
  run the exporter first for the 650-file version recorded here. Verified for this build: `testzip()` clean;
  all 650 entries re-hashed from inside the archive against its own MANIFEST.json, 0 mismatches, 0 missing.

  Rebuilding after committing anything changes the zip hash without changing the packaged content only
  where the content itself moved; provenance therefore lives beside the archive, in this file, never
  inside it (an earlier revision embedded `git HEAD` and that had to be undone - see the superseded log).

  python3 01_PROGRAM/restore_project_tree.py --into ../restored          # -> runnable PAPER_PROJECT tree

  This archive deliberately does record its own `git_commit` (in 09_ARCHIVE_METADATA/archive_build.json):
  provenance is the point of a reproducibility package, and the content checksum above exists so that the
  two can coexist - the zip hash answers "did I receive the exact file", the content checksum answers
  "is this the same package".
