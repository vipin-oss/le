# V-B10d_t3_1 — Tier-3 batch 1 (35 files): title page + printed DOI only

**Task.** First of eight tier-3 batches (274 files, ~35 per batch). Tier 3 asks for exactly two things per file — the **title page** and the **printed DOI** — plus a match against `LITERATURE_BASE.csv` by DOI first, then by author+year+journal, with name-only matches marked `AMBIGUOUS`. No tier-3 claim enters the manuscript, and `LITERATURE_BASE.csv` is **not** extended. Roster taken from `verification/DRIVE_PRIORITY.csv` where `tier = 3`, in `inv_id` order (DRV-0001 → DRV-0061 for this batch).

**Method.** Origin fetched (`e308a4d`). All 35 files downloaded by Drive id into `/tmp/gd/t31`, md5 recorded, page 1 extracted with `pypdf` (strict off), then a fallback chain for the one file that would not parse: `pikepdf`, then `PyMuPDF`. Metadata transcribed from the page only; where the page did not print a field, the field is `UNKNOWN` and the gap is stated in `notes` rather than filled from memory or from the file name. Matching: exact DOI against the base, then fuzzy title similarity (`difflib`, threshold 0.75 for a candidate) and a surname sweep for author+year+journal corroboration.

**Result.** 35 files, 33 matched nothing, 1 unidentified, 1 unreadable.

**The whole batch is outside the base.** Zero of 30 printed DOIs appear in the 495-row base, and the best title similarity across all 35 files is 0.68 — below any defensible match. On surname checks, the only near-collisions are false positives: `Guha` (LIT-0482, 2020, a different paper), `Aldandani` (LIT-0452, a different 2026 paper), `Mondal` (LIT-0070/0098/0447/0476, all different), `Sarkar` (7 rows, all different). So tier-3 is largely a **disjoint corpus**, which is consistent with tier-3 being metadata-only bookkeeping and with the standing rule that the base is not extended here. It is worth stating plainly in the report: the base cannot be validated from the library, and the library cannot be validated from the base.

**Two files defeated reading.** `DRV-0056` (`sensors-25-01401-v2.pdf`) is **truncated**: `pypdf` raises before it can count pages, `pikepdf` reports "root of pages tree has no /Kids array", and `PyMuPDF` opens it with **0 pages**. A second download is byte-identical (md5 `9b5f17e6…`), so this is reproducible, not a flaky transfer. `DRV-0055` (`ssrn-5403086.pdf`) is structurally fine but carries **no author, no venue, no year and no DOI** on its first page — only a title and an abstract. It is recorded `UNIDENTIFIED`; guessing SSRN from the file name would be exactly the kind of inference this task forbids, so the file name is mentioned in `notes` as a hint and not used as a field.

**Bibliographic defects worth flagging.** `DRV-0011` prints no journal name — only ISSN 2212-540X and the KeAi/Elsevier line — so the venue field says that, and nothing else. `DRV-0015` (book chapter) prints no publisher, book title or year. `DRV-0002`, `DRV-0003`, `DRV-0055` print no DOI at all. Several are **in-press copies** (0003, 0007, 0010, 0020, 0025, 0036, 0038, 0041, 0048, 0059, 0060, 0061) whose volume and pages are not yet assigned; those fields stay blank rather than being filled from a later web record. `DRV-0003`'s file name says 2027 while its page prints 2026 — the printed year was used and the discrepancy noted.

**Evidence / sources.** `verification/DRIVE_TIER3_METADATA.csv` (35 rows: inv_id, drive_id, file name, batch, year, authors, title, venue, volume/pages, printed DOI, DOI source, match status, matched LIT id, match evidence, read level, notes). Files were read 2026-10-22 and deleted from `/tmp` after the batch. DOI sample: `10.1016/j.euromechsol.2025.105786`, `10.1038/s41598-026-59340-x`, `10.1088/1402-4896/ad97eb`, `10.1007/s44198-024-00187-z`, `10.2478/ijame-2022-0055`, `10.1016/j.crhy.2013.09.011`, `10.1002/zamm.201800343`.

**Checks done.**
- md5 recorded for all 35 copies; the two failing files were re-downloaded and compared byte-for-byte before being declared unreadable.
- Three independent PDF engines tried on `DRV-0056` (pypdf → pikepdf → PyMuPDF) before `UNREADABLE`.
- Match checked twice per row: exact DOI lookup, then title similarity, then a surname sweep (`Guha`, `Sur`, `Das`, `Gupta`, `Pathania`, `Mondal`, `Sarkar`, `Janssen`, `Algahtani`, `Aldandani`, `Meghana`, `Vijay Kumar`, `Alshahloub`) to make sure a fuzzy miss was not hiding a real duplicate.
- `DRIVE_TIER3_METADATA.csv` row count 35, `inv_id` unique 35/35; `DRIVE_PRIORITY.csv` updated for the same 35 (`batch = T3-1`, `read_level`) and still 370 rows.
- `LITERATURE_BASE.csv` untouched at 495 rows, `FULLTEXT_FACTS.csv` untouched at 96.
- `/tmp/gd` deleted; `google_drive/` strays removed before commit.

**Confidence.** HIGH on the transcription — every field was read off the page, and the blank fields are blanks on the page. HIGH on `DRV-0056` being unreadable (three engines, reproducible bytes). HIGH that the batch does not match the base (DOIs are printed and absent; title similarities are all below 0.7). MEDIUM on individual fuzzy-negative judgements: a title similarity of 0.58 cannot by itself exclude a duplicate, which is why the surname sweep was added and why the `match_evidence` column records what was actually compared.
