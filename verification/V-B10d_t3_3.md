# V-B10d_t3_3 — Tier-3 batch 3 (35 files): title page + printed DOI only

**Task.** Third tier-3 batch, `DRV-0105 → DRV-0160` (35 files). Title page and printed DOI only; match against `LITERATURE_BASE.csv` by DOI first, then author+year+journal; `AMBIGUOUS` for name-only. No tier-3 claim enters the manuscript; the base is not extended.

**Method.** All 35 downloaded by id, md5 taken. Page 1 extracted with `pypdf`; where it failed or was a cover/watermark page, `PyMuPDF` was used and the article page read instead (this batch has four such cases: two Iranian *Journal of Solid Mechanics* papers whose page 1 is a scanned cover, and several ResearchGate covers). Two files defeat every engine. Matching computed against the base **and** against the DOIs already recorded in this tier-3 file, which is how the duplicate pair below surfaced.

**Result.** Eight of 35 resolve.

* **Five exact DOI matches to base rows:** `DRV-0128` → **LIT-0412** (Sur & Kanoria, `10.1016/j.tws.2017.05.005`), `DRV-0133` → **LIT-0305** (Kant & Mukhopadhyay, `10.1177/1081286518755562`), `DRV-0136` → **LIT-0303** (Ezzat, El-Karamany & El-Bary, `10.1080/09205071.2015.1027795`), `DRV-0139` → **LIT-0285** (Sarkar & Mukhopadhyay, `10.1080/01495739.2019.1642169`), and `DRV-0105` → LIT-0491, which is also the paper of the **tier-2 file DRV-0146**.
* **Two copies of one paper sit inside the library, in two different tiers.** `DRV-0105` (*WRCM* 2020, Kaur/Lata/Singh, `10.1080/17455030.2020.1856451`) is byte-for-byte a different file but bibliographically the same paper as `DRV-0146` in tier 2. `DRV-0129` (*MAMS* 2019, Sarkar/Ghosh/Lahiri, `10.1080/15376494.2018.1432784`) is the same paper as `DRV-0062` in batch 2. Both are recorded `DUPLICATE-WITHIN-LIBRARY` with the twin named. Tracking the duplicates matters because the Drive inventory counts files, not papers: the 370-row priority list overstates the distinct-paper count by at least these two.
* **Two files are again truncated exactly like the tier-2 pair:** `DRV-0126` ("unable to find trailer dictionary") and `DRV-0142` ("root of pages tree has no /Kids array"), both opening as 0 pages in PyMuPDF. This is now the **fourth and fifth** occurrence of the same failure mode, always on a file whose size is an exact multiple of 1024 bytes. It is a delivery defect, not a library-content judgement, and it should be reported to whoever owns the Drive folder.
* 27 files match nothing.
